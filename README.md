# Sync Music

Синхронізація файлів між комп'ютером (Windows) і телефоном (Android) через Wi-Fi у домашній мережі. Без хмари й без обмежень на обсяг.

- **На комп'ютері** працює програма Sync Music. У ній додаються папки для синхронізації, і для кожної вказується напрямок: **ПК → телефон** (за замовчуванням) або **телефон → ПК**. Там само вмикається перемикач «видаляти файли, видалені в джерелі». Програма показує для кожного телефона й кожної папки, скільки вже синхронізовано, скільки залишилось, швидкість і приблизний час до кінця.
- **На телефоні** для кожної папки вибирається своя папка: у пам'яті телефона або на SD-карті. Застосунок працює у фоні: кожні 15 хвилин і щоразу при відкритті перевіряє, чи увімкнено комп'ютер, і синхронізує все в потрібних напрямках з докачуванням після обриву.
- Синхронізуються всі файли, крім прихованих і системного сміття (Thumbs.db, desktop.ini, тимчасові файли Office).
- Видаляються лише ті файли, які приніс сам Sync Music. Якщо папка-джерело порожня або недоступна, нічого не видаляється.

## Встановлення

1. Відкрийте [останній реліз](../../releases/latest).
2. **Комп'ютер:** завантажте `SyncMusic-x.y.z.msi` і запустіть. Права адміністратора не потрібні. Якщо інсталятор не підходить, розпакуйте `SyncMusic-x.y.z-portable.zip` і запустіть `SyncMusic.exe`.
   - Під час першого запуску Windows може запитати про доступ до мережі: натисніть **«Дозволити доступ»**.
3. **Телефон:** наведіть камеру телефона на QR-код у вікні програми на ПК, завантажте й установіть застосунок (Android попросить дозволити встановлення з браузера).
4. У застосунку на телефоні натисніть **«Знайти комп'ютер»**, виберіть свій ПК і введіть 6-значний код з екрана комп'ютера.
5. Надайте застосунку дозволи: «Доступ до всіх файлів» (щоб класти музику в папку Music) і «Робота у фоні».
6. У блоці **«Папки»** на телефоні виберіть, куди зберігати кожну папку з ПК (або залиште запропоноване місце). Для папок «телефон → ПК» виберіть, яку папку телефона надсилати.

Далі все працює саме. Оновлення: нова версія програми для ПК приносить із собою й нову версію застосунку, а телефон сам запропонує оновитися.

## Якщо телефон не знаходить комп'ютер

- Телефон і комп'ютер мають бути в одній Wi-Fi мережі, не в гостьовій мережі й без режиму «ізоляції клієнтів» у роутері.
- У програмі на ПК натисніть **«Дозволити в брандмауері»** (Windows попросить підтвердження адміністратора).
- Адресу можна ввести вручну: вона показана у вікні програми на ПК («Адреса комп'ютера для ручного введення»).

## Папки на телефоні й SD-карта

- Для папок «ПК → телефон» місце пропонується автоматично: для музики з першої версії — `Music/Sync Music`, для решти — `Sync Music/<назва папки>`. Його можна змінити кнопкою «Змінити». Тоді файли заново завантажуються з комп'ютера, а зі старого місця їх можна видалити або залишити.
- Android 11 і новіші: можна вибрати будь-яку папку в пам'яті телефона або на SD-карті.
- Android 8–10: система дозволяє писати на карту лише в папку застосунку (`Android/data/biz.fesh.syncmusic/files`), і файли звідти видаляються разом із застосунком.
- Якщо вибрану карту вийнято, ця папка не синхронізується, доки карту не повернуть.

## Як це влаштовано

| Частина | Технології |
|---|---|
| ПК | Kotlin + Compose Desktop, вбудований HTTP-сервер Ktor (порт 45456), UDP-виявлення (порт 45455), значок у треї, автозапуск |
| Телефон | Kotlin + Jetpack Compose, WorkManager (фонова робота, foreground service типу dataSync), OkHttp |
| Спільне | Модуль `shared`: протокол і форматування |

Протокол:

1. Телефон розсилає UDP-broadcast `SYNCMUSIC_DISCOVER_V1`, комп'ютер відповідає своєю назвою і портом.
2. Сполучення: телефон надсилає одноразовий 6-значний код з екрана ПК і отримує постійний токен.
3. Папки: `GET /api/folders` (список папок ПК з напрямком і перемикачем видалення).
4. ПК → телефон: `GET /api/manifest?folder=` (файли з розміром і датою) → порівняння → `GET /api/file` з докачуванням через HTTP Range.
5. Телефон → ПК: `GET /api/manifest?folder=` (що вже є на ПК) → `GET /api/upload/offset` + `PUT /api/upload` (докачування з місця обриву) → `DELETE /api/file` для файлів, видалених на телефоні (якщо видалення ввімкнене).
6. `POST /api/progress` щосекунди, щоб ПК показував прогрес по кожній папці.

Кожна папка синхронізується в один бік. Якщо папка-джерело недоступна або порожня, на приймальному боці нічого не видаляється.

## Автоматична перевірка

Після кожного пушу в `main` GitHub Actions, крім збірки, проганяє наскрізний тест (`ci/e2e_android.py`): справжня ПК-програма (Linux-збірка) і Android-емулятор, керування через adb. Тест перевіряє:

- сполучення за кодом (і відхилення невірного коду);
- оновлення з попередньої версії без повторного завантаження вже синхронізованих файлів;
- першу синхронізацію з побайтною перевіркою файлів;
- видалення на ПК (лічильник оновлюється сам, на телефоні файли й порожні папки зникають);
- відновлення файлу, видаленого на телефоні; нові та змінені треки;
- обрив завантаження великого файлу й докачування з місця обриву;
- 28 000 файлів, скопійованих на телефон кабелем (приймаються без повторного завантаження), і їхнє масове видалення;
- папку «телефон → ПК»: вибір папки на телефоні, надсилання, перемикач видалення, докачування великого файлу після обриву;
- другу папку «ПК → телефон» (приховані файли й Thumbs.db не передаються);
- перенесення папки на SD-карту через вибір папки в застосунку;
- реакцію телефона на відключення на ПК.

На Windows-машині CI програма запускається по-справжньому: скриншоти, час запуску, повторне відкриття з трею. Звіт, скриншоти й журнали лежать у гілці `ci-logs`. Реліз публікується лише тоді, коли тест пройшов.

## Збірка

Збирається автоматично в GitHub Actions після кожного пушу в `main`: APK (Ubuntu) → вкладається в програму для ПК → MSI і portable-zip (Windows) → реліз `v1.0.<номер збірки>`. Логи останньої збірки лежать у гілці `ci-logs`.

Локально (JDK 17, Android SDK):

```
./gradlew :androidApp:assembleRelease
./gradlew :desktopApp:run
```
